# Tungsten IDE 2.1

Tungsten 2.1 is a focused workstation-depth release. It keeps the browser workspace and hardened Electron boundary while improving startup delivery, multi-root projects, Git review, test feedback, terminal continuity, and collaboration presence.

## Performance

The renderer is no longer shipped as one Monaco-heavy entry file. Monaco, its language workers, React, and xterm are emitted as explicit chunks, while the configured editor and terminal UI are loaded on demand.

Validated production build sizes:

| Chunk | Uncompressed | Gzip | Loading |
| --- | ---: | ---: | --- |
| Renderer entry | 121.24 kB | 35.95 kB | Initial |
| React runtime | 211.00 kB | 65.85 kB | Initial |
| Monaco editor core | 4,392.97 kB | 1,123.06 kB | Lazy |
| xterm core and search | 364.47 kB | 92.81 kB | Lazy |

The previous renderer entry was approximately 4.6 MB (1.19 MB gzip). Monaco workers remain local and use the relative imports already validated in packaged builds.

## Multi-root workspaces

Use the **Add workspace root** control in Explorer to mount up to eight additional local roots. Tungsten:

- gives each added root a stable `@name` virtual prefix;
- aggregates bounded traversal and ripgrep results;
- watches all roots and reports virtual paths to the renderer;
- resolves reads, writes, renames, deletes, and DAP paths inside the owning root;
- persists and restores the root list;
- initializes LSP servers with every workspace folder and sends folder-change notifications; and
- prevents traversal and symlink writes from escaping each owning root.

Git operations remain intentionally scoped to the primary root, avoiding accidental cross-repository commands.

## Git workstation

Selecting a changed file opens a read-only side-by-side Monaco comparison:

- unstaged changes compare the working tree with the index;
- staged changes compare the index with `HEAD`;
- every diff hunk has a stage or unstage action; and
- whole-file staging and unstaging remain available in Source Control.

Hunk patches are bounded, validated, and sent to `git apply --cached` through stdin rather than interpolated into a shell command.

## Structured testing

Discovered JavaScript/TypeScript, Python, Go, and Rust tests can run as individual structured jobs. Tungsten records pass/fail state, exit code, duration, stdout/stderr, focused failure lines, snapshot-related output, and refreshed LCOV data. Results remain attached to each test in the Testing sidebar.

## Terminal continuity

Terminal tab labels, selected tab, profiles, split state, and workbench panel dimensions persist between sessions. Terminal output can be searched with xterm's search addon. Local commands launched from Tasks now receive dedicated task-labelled PTY tabs. WSL and running Docker targets appear in the profile selector when detected.

Persistent layout restores terminals as fresh PTY processes; it does not serialize live shell processes across application restarts.

## Collaboration

Active collaborators now publish cursor file, line, and column presence. Remote cursor positions are rendered in Monaco and include a collaborator hover label. Joined clients retry room connections after transient disconnects while Yjs synchronizes document state after reconnection.

## Validation

The 2.1 source gate includes ESLint, 16 Vitest checks, TypeScript, the production Vite build, production HTTP E2E, native PTY smoke, Git hunk-application smoke, IPC bridge parity, workspace benchmark, and dependency audit. Installer artifacts are generated by the cross-platform workflow and remain unsigned unless signing secrets are configured.
